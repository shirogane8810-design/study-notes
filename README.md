# 学習ノート

公開URL：https://shirogane8810-design.github.io/study-notes/

自分専用の学習ノートPWA。科目 → 授業回 → PDF＋テキストノートの構成で、8段階の順序を維持して開発します。

## 起動

Node.js 22.13以上を用意し、このフォルダで実行します。

```sh
npm ci
npm run dev
```

表示されたローカルURLをChromeで開きます。開発サーバーは127.0.0.1のみで待ち受けます。

本番用PWAの確認：

```sh
npm run build
npm run preview
```

Service Workerは本番ビルドにのみ入ります。初回はオンラインで読み込み、Service Workerが有効になってからオフラインにします。

## GitHub Pages

1. このフォルダの中身をGitHubリポジトリのルートへ配置します。公開用ファイルに個人の学習資料を入れないでください。
2. リポジトリのSettings → Pages → SourceをGitHub Actionsにします。
3. mainへのpushまたはDeploy to GitHub Pagesの手動実行で、テスト・ビルド後に配信します。
4. Viteのbaseは`./`なので、リポジトリ名のサブパスでも動作します。History APIルーティングは使いません。

本アプリに認証はありません。GitHub Pagesのアプリは一般公開され、ノートはアクセスした各ブラウザのIndexedDBに保存されます。本人のデータはサーバーに送信しません。別の人が同じURLを開いても、その人自身の空のデータベースを使用します。同じ端末・ブラウザプロファイルを使う人はノートを閲覧できます。

iPadのSafariではGitHub PagesのURLを開き、共有 → ホーム画面に追加します。PC Chromeではアドレスバーのインストール操作を使います。端末間のデータ同期はありません。URL（オリジン）が変わると保存先も変わります。シークレットモードやサイトデータ削除でデータが失われる場合があります。フェーズ5でZIPバックアップを追加します。

## 設計上の判断

- React＋Vite＋TypeScript strict、Dexie／IndexedDB。アプリ実行中の外部API、サーバー、外部フォント、CDNは使わない。
- スキーマv1は全8段階のエンティティを用意する。後続の型の具体化とスキーマ変更はDexieのバージョンを上げて行う。
- 科目／授業の作成・編集はダイアログの確定時に即時保存。手書きは250msデバウンスとストローク終了時の即時保存を併用する。
- デモデータは自動投入しない。最初の一覧は空で、個人の科目を追加できる。
- 授業の回数と表示順は独立。並べ替えで第N回の値は変更しない。タッチ用に上下ボタンも用意する。
- 関連データの削除はトランザクションで行い、他科目を巻き込まない。テストで関連PDF・ストローク・カード・履歴の削除を検証する。
- 保存容量不足などは日本語のエラーを出す。データ保存前に成功表示しない。
- 試験のデータ型はフェーズ1に用意するが、登録・カウントダウン画面はフェーズ7で実装する。
- ライト／ダーク設定もIndexedDBへ保存。プライバシー上、保存データは同じURLを開く他端末と共有しない。
- PWAの更新は再読み込み案内を表示し、作業中の自動再読み込みを避ける。
- Sitesへの配置は行わず、ユーザー指定のGitHub Pagesを想定する。

## フェーズ2の設計上の判断

- PDF.js（Apache-2.0）を使用する。Worker、CMaps、日本語表示用リソース、標準フォント、WASMもローカル配信し、PWAに事前キャッシュする。外部CDN・外部APIには接続しない。
- PDFのWorkerと補助データを含む初回キャッシュは約5.5MB。`predev`と`prebuild`で依存パッケージから補助データを準備する。`public/pdf-assets/`は自動生成物としてGit管理から除外する。
- PDF1ファイルは100MBまで。パスワード付きPDFはフェーズ2では非対応で、日本語エラーを表示する。正常に開けたものだけ元Blobとページ参照をIndexedDBへ保存する。1授業に複数のPDFを追加できる。
- PDFのテキスト抽出はフェーズ4で実装する。現在のextractedTextは空配列。
- 各ページのサイズだけを事前取得し、表示範囲＋前後1ページのCanvasだけを保持する。画面外のページは高さを持つプレースホルダー。選択中ページのPDF描画は最大2倍、周辺ページは1倍、1枚のPDF Canvasは最大600万画素に制限する。
- 正規化座標は、そのページの元の表示方向（PDF自身の回転を含む）を基準に保存する。ユーザーによる追加回転を逆変換して記録する。線幅も基準ページ幅に対する比率で保存する。
- PDF、蛍光ペン、ペン、描画中ストロークを別のCanvasに分ける。蛍光ペンは半透明＋multiplyで文字を覆い隠さない。保存済みの線を毎ポインターイベントで描き直さず、描きかけだけをrequestAnimationFrameで更新する。
- `getCoalescedEvents()`が利用できない環境は通常のPointerEventにフォールバックする。マウスは一定筆圧、ペンは実測筆圧を使う。
- Pencil描画中は指のスクロールも抑制する。通常はタッチを描画に使わず、指のスクロール・2本指ピンチはPDF閲覧領域内で処理する。ブラウザ全体の拡大操作とは独立する。iPad相当の幅ではPDF編集中のサイドバーを折りたたみ、上部メニューで科目一覧を開ける。
- ドラッグ中のストロークを250msでデバウンス保存し、ストローク終了時は即時に保存を開始する。画面／資料切り替えとPWA更新は保留中の保存完了を待つ。容量不足時はエラーと再試行を表示する。
- Undo/Redoは資料ごとに最大100操作。同じ消しゴム操作で消した複数のストロークを1操作として扱う。元PDFは変更せず、書き込みを別保存する。
- Strokeに任意のcreatedAtを追加し、重なるペン線の描画順を再読み込み後も維持する。IndexedDBの既存v1データを壊さない追加フィールドで、フェーズ1の科目や授業はそのまま使用できる。
- ブラウザ／端末の強制終了時は、最後の未確定・保存中の線が失われる場合がある。「保存済み」表示を確認して閉じる。ZIPバックアップはフェーズ5で追加する。

## フェーズ3の設計上の判断

- PageRefのsrcPageと表示上のpageIndexを分け、挿入後も元PDF参照を維持します。挿入時は手書き・文字注釈・カード・確認済みページの番号を1トランザクションでずらします。挿入前に保留中の書き込みを保存します。
- 挿入用紙はA4相当595×842ptです。ページ挿入後は新しいページを開き、Undo履歴をリセットします。ページ挿入そのもののUndo／削除／並び替えは現時点ではありません。
- 投げ縄は囲みと交差するストロークを丸ごと選択し、筆圧・形を維持してページ内に移動します。移動・削除・色変更はそれぞれ1操作でUndo/Redoできます。投げ縄は手書き用です。

- JSONはsummary（points3〜5個、terms30個まで）とquestions（1〜50問）です。kindはmcqかshort。question/answer/explanationとsourcePageが必須で、sourcePageはコピー範囲内の表示ページ番号、または本文が根拠ならnullです。4択のchoicesは異なる4文字列、answerは正解の選択肢と一致させます。
- jsonコードブロック1個またはJSON本体を受け付けます。不正なJSON、未知の項目、重複問題、不正な根拠ページ等を日本語の項目位置とともに拒否します。回答50万文字、指示文1万文字までです。
- 明示的な取り込みで要約と新規FSRSカードを同一トランザクションに追加し、既存ノートやカードを保持します。同じ回答を再度取り込めば追加されます。準備後にPDFページ構成が変われば取り込みを止めます。カードの根拠は固定ページキーで追跡します。
- 4択の誤答では即座にrating1と履歴を保存します。連打や二重評価を防ぎ、直前評価の取り消しで期限と履歴を戻せます。正解は記憶の難しさを利用者が評価して保存します。
- 試験・確認済み・AI要約・問題・復習履歴は既存ZIPバックアップに含めます。DBはv3のままで既存データを保持し、新しい外部依存は追加していません。

## フルスクリーン学習表示（2026-10-03）

PDFの「フルスクリーンで表示」を押すと、左上に授業名と資料名、左下に筆記ツール、右下にノート開閉・終了を表示します。ツール設定で色・太さ・Undo・ページ操作を展開します。二本指の短い静止タップで案内を表示し、12px以上の移動や450ms以上の長押しは除外します。ピンチズームは継続します。Fullscreen API未対応の環境ではブラウザ内の全画面表示を使います。

既存のPDF編集とTipTapのDOMを維持し、表示だけを切り替えます。IndexedDBの名前・テーブル・バージョン・保存形式、ZIP形式は変更していません。データ初期化・削除・再インポートは不要です。PWAは起動時・画面に戻った時・オンライン復帰時・1時間ごとに更新を確認し、既存の保存後再読み込みで適用します。

検証手順：資料を開き全画面にする→ノート開閉→入力→ツール設定→終了→再表示・再読み込みで内容を確認。タッチ実機では二本指タップとピンチを確認してください（自動操作では実機ジェスチャー未検証）。

### PCの二本指タップ対応（2026-10-03）

PCトラックパッドの二本指タップは、タッチ画面の二点接触ではなく右クリック（contextmenu）として届きます。通常表示のPDF閲覧領域では、このイベントを「フルスクリーンで表示」の案内に切り替えます。マウス右クリック・キーボードのコンテキストメニュー操作も同じです。文字入力欄では標準の編集メニューを保持します。右ボタンでは手のドラッグを開始しません。保存形式・既存データへの変更はありません。
